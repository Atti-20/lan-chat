# 协议、跨端设计体系与工作区整理

日期：2026-09-08。用户明确选择 Web/Vue、桌面/Vue+Tauri、移动/Flutter、后端/Spring Boot 的目标路线；本轮主要完善协议与设计体系，并整理凌乱的项目目录。

## 目标

- 协议从说明和源码索引推进为可生成、可校验的机器契约，保持现有服务行为与消息兼容。
- 将设计体系提升为平台无关的数据源，Vue / Flutter 生成值一致，补齐组件状态、平台差异和验证规则。
- 清理或归档有依据的冗余文件，统一当前规范入口；保留未提交源码、用户数据、凭据与必要证据。
- 更新目标架构与迁移状态，明确 Capacitor 是迁移期间的现有客户端，Flutter 尚未完成全部业务迁移。

- [x] REST / WebSocket 结构契约、TS 与 WS Dart 类型生成及对应检查落地；完整 SDK 范围另列。
- [x] 平台无关设计源、CSS / Dart 生成、设计规范与自动校验落地。
- [x] 工作区库存、引用检查、清理/归档与可追溯记录完成。
- [x] 受影响模块测试、构建、视觉或真实契约验证完成，边界如实记录。

## 验收基线

基线：`output/protocol-design-workspace-2026-09-08/baseline-hashes.json`。上一轮目录迁移已落地，但根仍有 out / target 等旧编译输出，以及 PRD / TODO / spikes 等历史材料。当前 REST 尚无完整 OpenAPI，WS 仅客户端信封 schema；设计 CSS 为源，Flutter 仅提取部分值。

## 约束

不依据文件名批量删除未知数据。先检查真实引用和运行依赖；历史文档、截图、日志保留并更新链接。清理优先可逆归档。协议/认证行为不因文档化而改变。新设计值生成应先保持现有视觉值，再以规范约束新界面。
