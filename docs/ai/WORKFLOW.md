# 协作、任务与交接

## 新会话

1. 读根适用 AGENTS/override、用户指定任务和上一阶段 handoff，先核对 Git 状态。
2. 目标入口不明确时从 [INDEX](INDEX.md) 选一个任务路由；按需读适用模块指令、少量实现及现有测试，不重复读取本会话已读且未变化的资料。跨模块再读关联架构/ADR。
3. 有修改且验证命令不明确或运行器变化时，用 dry-run 确认命令和产物目录；只执行当前授权阶段，不从历史 TODO 或已完成任务自动接续。

编号治理任务的单一状态保存在 `docs/tasks/active/MX-*.md`，索引见 [tasks](../tasks/README.md)。复用 [执行计划模板](../exec-plans/template.md) 的状态/验证/handoff 字段，不另复制相同计划。没有指定编号位置的跨会话任务继续使用 `docs/exec-plans/active/`，完成后归 completed；用户指定保留的任务路径保持不变。

## 交付要求

编号治理或跨会话任务使用完整任务卡，普通修改只简报修改、验证及遗留边界。任务卡包含目标、非目标、branch/HEAD、已有改动、实际修改文件、命令/cwd/退出码/环境、四种状态、证据路径、遗留问题、下一任务启动条件和回滚边界。报告与证据规则见 [docs/AGENTS.md](../AGENTS.md)。完成当前授权范围的实现和相关验证后停止；用户已授权连续阶段时可继续，否则不启动下一张任务。

短期日志、完整 API、历史计划和报告不进入根 AGENTS。模板里的例子不是实现事实。无关旧报告、output/target/node_modules 默认不检索；当复现需要时再针对性展开。

## 模型分工与升级

- 默认单代理，小范围修改不派生；同一时刻最多一个子代理。
- 需要委派且能独立拆分的只读路径探查、日志归纳、文档核对可用 `lan_chat_scout`；主线程综合和实现。
- 涉及鉴权、事务、并发、WebSocket、消息一致性或跨端风险的实际代码形成后，可用 `lan_chat_reviewer` 做一次只读审查。
- 只有已有复现证据，且两次不同证据的定位/修复仍不能解释；或问题同时跨 server、Vue、桌面/Android 且无法确定边界时，才用 `lan_chat_astra_escalation`。仅诊断和验证策略，不修改文件。
- 不为常规规划、简单修改或重复检查使用 Astra/并行代理；不给子代理超出当前用户任务的修改或对外操作权限。
