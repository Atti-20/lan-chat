# ADR 0005：按需上下文与协议事实来源

日期：2026-09-08。状态：采纳，延续 ADR 0001 与 ADR 0004。

## 背景

工作区已经分层、设计值已有共同来源，继续重命名目录不能解决每次重复检索和资料漂移。旧 REST 索引靠注解正则，漏掉无参数的 `@GetMapping`；此外，完整 OpenAPI 不适合每次作为初始上下文加载。

## 决策

1. 根 AGENTS 保留导航与稳定约束，细节留在模块指令和按主题组织的规范中。工作区清单显式记录相关文档与验证范围，context 只输出目标模块的短导航；预算按 UTF-8 字节校验，不猜测模型 token 或节省比例。
2. 现有 REST 采用 Controller / DTO → MVC 测试导出 OpenAPI → 生成类型和导航的链路。快照记录实际声明方法的 x-source，用于准确链接源码；这是生成元数据，不改变网络字段。普通测试检查漂移，更新快照需要审阅差异。暂不反向生成或重写既有 Java Controller。
3. WS schema 与 token JSON 保持各自的字段/设计来源。协议的开放字段和只覆盖方向的事件继续显式标记，不把生成成功当成完整业务验证。
4. 保留当前包和应用边界：共享 Vue 已被 Web/Tauri/Capacitor 复用，API 编排仍依赖应用状态。出现独立消费者、清晰依赖和独立测试后再提取 api-client / ui-vue；Flutter 迁移按 ADR 0004 验收，不通过改名宣告完成。

## 事实冲突处理

- 协议字段查已验证结构契约；权限、事务、幂等与错误触发查真实实现及行为测试。两者冲突先复现并修正漂移，不能盲目以过期契约覆盖运行行为，也不能忽略兼容约定只改实现。
- SQL 初始化/迁移文件描述计划结构；判断某个数据库当前状态必须读取对应实例的迁移与表结构证据。
- 设计值查 tokens.json；渲染结果查实际客户端。截图不反向覆盖 token，生成值也不能证明 UI 已验收。
- ADR 描述选择理由和目标；ARCHITECTURE 描述现行边界。一般说明、历史报告、注释与生成索引提供导航，不创造第二套协议定义。

这是不同问题的证据分工，不是“任何契约文件都永远高于代码”的统一排序。

## 依赖方向

箭头表示导入依赖：`domain-ts → protocol`；`platform-ports → domain-ts / protocol`；`平台适配 → platform-ports`。应用层组合接口与实现。共享领域不导入 Vue、DOM 状态或原生 SDK；不要把 UI 到系统 API 的运行调用流程画成相反的源码依赖规则。

## 后果与验证

新增映射、源码位置或模块入口都能通过生成检查发现漂移；初始导航保持短小，具体 schema 和跨平台细节按需展开。运行 `python3 -m unittest discover -s tooling/tests`、`./tooling/verify workspace`，REST 相关变更再执行 `./tooling/verify contracts`。真实 token 成本和任务成功率需另行采样，本决策不承诺“80% 任务”或固定节省比例。
