# MX-A07 — 产品功能对齐与多端发布门禁

前置：A06。目标是按真实基线逐项对齐，不把架构重构扩张为所有新需求一次交付。

## 操作

建立 Web、Tauri、Android、iOS 的功能矩阵：会话、文字/图片/文件、好友、群组、广播/回执、临时房间、当前直传与回退、设置/主题等，以实际存在的功能为准。标明完成、计划、降级、不支持、未测试。Harmony 单独规划，不标成已支持。

一次迁移一个功能切片，沿服务端/契约/TS/Dart/设计/平台测试同步推进。尚未实现的新群管理规则、广播流程或企业发现等需求，另开 feature 任务，不混进“无行为变化”的重构 PR。

完成可复现构建、契约再生成无 diff、import 边界、TS/Dart 共用向量、Web视觉/Flutter golden、原有 hygiene、安全凭据检查以及对应 OS 构建。依赖影响范围矩阵必须验证删除/重命名和共享变更传播。

准备发布说明、兼容范围、数据升级与备份策略。保留旧应用标识和安装升级路径；验证已有用户配置/缓存升级，而不是仅测全新安装。回滚流程不以删除数据库或清除应用数据为前提。

## 验收

每项功能有最少一条跨端真实场景证据；旧客户端与新后端兼容策略有测试；明示未覆盖设备/系统。不能用 flutter test 或 npm test 的总绿结果声称全平台验证完成。

## 非目标

不自动推送/合并/商店提交，不把 CI 通过等同于人工授权发布。签名和推送凭据通过安全机制配置，禁止写入仓库。需要产品取舍和最低版本变化时明确列出决策，不由 Codex 默默选择。
