# MX-A06 — 系统能力、通知/发现和真机质量

前置：A05。此任务建议拆成每个能力一个小 PR，但同一任务交接保持连续。

## 按优先级实现

先文件选择/分享与取消、上传恢复，再局域网发现及授权，再通知/推送注册，最后前后台/休眠/恢复策略。只实现产品确实需要的能力，不为凑端数量写空 adapter。

成熟插件能满足维护、许可、系统下限和功能时优先封装；不足时用本地 Flutter 插件 + Pigeon + Kotlin/Swift。核心不依赖具体插件。

Discovery 定义 start/stop/watch/cancel/timeout、权限/不支持/暂不可用及空列表区别；拒绝权限后提供手动服务器输入。不要自动信任广播端点或给发现节点发送现有 token。发现用户不等于加好友成功。

Notification 区分本地展示与远程推送。推送提供方和账号设备 token 的服务端映射独立设计；不硬绑所有 Android 为 GMS。通知点击路由、应用退出/账号切换、通知拒绝必须测试；推送负载不得包含不必要的敏感聊天内容。

Lifecycle 核心是恢复时重新验证会话和补同步。iOS 不承诺纯 LAN 后台常驻；Android 前台服务只能使用合规场景和类型，不默认以常驻服务代替正确同步。不用音频/VoIP/定位假用途绕过限制。

## 真机验收

至少在可获得的 Android 真机与 iPhone 上记录：同网发现、拒绝/撤销权限、网络切换、休眠恢复、通知点击、退出换号、文件选择取消、大文件失败/恢复。Android 需要覆盖目标 OEM 的实际后台限制，不以模拟器替代。脱离调试器复查后台行为。

验证预测性返回/系统返回、输入法遮挡、多窗口尺寸、安全区与系统通知；功能只在支持系统上启用，老系统有合理降级。

## 交付与回滚

能力支持矩阵注明系统/设备/网络环境、测试日期和实际结果。未能测试的格子保留未知。某适配可独立禁用或回退到手动输入/站内提示/前台同步，不影响基础聊天，不提升最低支持版本来掩盖问题。
