## 范围与决策

- 以 [B02](../../product/mobile-v0.3.1-work-plan.md#b02-移动导航与会话整合) 和 Web `AppRail` 的当前产品结构为事实输入。

- Flutter 将原“更多操作”中的 P0 功能提升为常驻底部主导航。联系人选择、建群成功和群详情进入聊天回到消息页；非消息一级页系统返回先回消息页。
- 页面按首次访问延迟创建，避免登录后同时加载好友、群聊和广播。个人资料入口在每个一级页面可达；主题和退出仍由资料设置页维护。
- 现有 Web 的“好友 / 群组”局部文案差异记录为后续文案债；本卡不扩大为 Web 视觉重构，不把桌面管理台搬到移动端。

## 联系人申请与广播待办主导航计数（2026-09-14）

新增`lib/application/navigation_counts_controller.dart`，读取现有friendRequests与pending broadcasts接口，按请求/广播ID去重；好友仅计toUserId为当前账号且status=0的待处理申请。null表示未知且隐藏，不能用0假装读取成功。消息、申请、广播的语义和数字相互独立；复用现有Badge并提供准确中文读屏标签与99+视觉封顶。

API实例+userId+同步就绪状态决定计数owner，切换/断线立即清空并递增epoch；旧响应、销毁后的响应不能回写。每类请求只允许同epoch一个在途请求，期间多次事件合并为一次后续刷新。启动就绪、friendChanges/broadcastChanges、切换一级目的地、重连后刷新摘要；不提前构建完整联系人/群聊/广播页，不新增后台轮询。

`ChatController`新增本地申请/广播变更通知方法，复用原有stream；FriendsController处理申请成功后通知（包括拒绝），BroadcastsController在服务端办理成功后通知，即使后续详情读取失败也会重新核对摘要。没有修改REST/WS协议、服务端权限或数据库。ChatPage管理计数控制器生命周期并在替换ChatController时重建。

新增4个controller回归覆盖独立计数/过滤去重、请求失败隐藏、旧账号/断线迟到响应、20个事件合并、销毁；widget回归覆盖320px/1.4倍字浅深主题、两类读屏标签及各自办理后清除。已有好友/广播业务测试增加成功通知断言。首轮测试因异步箭头表达式后的cascade绑定到List编译FAIL，改为独立赋值后定向11项PASS；统一Flutter六组PASS，170项测试（`output/mx-navigation-counts-2026-09-14/flutter.json`）。workspace首次因新增文件导致generated repo-map过期而FAIL；执行官方generate后复验PASS（同目录`workspace-final.json`），不手改生成文件。
