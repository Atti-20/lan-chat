# MeshX 跨端信息架构与导航

更新：2026-09-14（MX-A07B-10 / B02）。本规范扩展 [跨端设计体系](README.md)，统一产品入口、命名、层级和返回语义；不要求 Web 与 Flutter 使用相同布局，也不建立第二套颜色或组件库。

## 统一模型

登录后的普通用户工作区固定为四个一级目的地：

| 产品目的地 | 统一名称 | Web / 桌面 | Flutter 移动 | 包含 |
|---|---|---|---|---|
| `messages` | 消息 | 左侧主导航 | 底部主导航 | 会话列表、私聊、群消息、附件消息 |
| `contacts` | 联系人 | 左侧主导航 | 底部主导航 | 好友、申请、搜索、进入私聊 |
| `groups` | 群聊 | 左侧主导航 | 底部主导航 | 我的群聊、建群、成员、进入群聊 |
| `broadcasts` | 广播 | 左侧主导航 | 底部主导航 | 待办、全部广播、详情与回执 |

个人资料、主题、权限、支持信息和退出属于账户层，不与内容目的地竞争。Web / 桌面使用主导航底部头像；Flutter 在各一级页面右上角提供“个人资料与设置”。重新连接是连接状态的恢复动作，不是一级目的地。管理员工作台只保留在已有 Web / 桌面入口，移动端不显示伪入口。

## 平台映射

```text
Web / desktop                Flutter phone
┌────┬────────┬──────────┐   ┌──────────────────────┐
│主导│ 列表   │ 内容     │   │ 标题 · 节点连接状态  │
│航  │        │          │   ├──────────────────────┤
│    │        │          │   │ 当前一级页面 / 详情  │
│头像│        │          │   ├──────────────────────┤
└────┴────────┴──────────┘   │消息│联系人│群聊│广播 │
                              └──────────────────────┘
```

- 宽屏使用并列列表和内容；手机使用单栏逐层进入。会话列表和各一级页显示四目的地底部导航；进入具体会话后暂时隐藏，系统返回回到列表后恢复，不把 P0 功能收进溢出菜单。
- 节点名称和连接状态是 LAN-first 产品的识别元素：消息页标题下持续显示，但不靠颜色单独表达在线状态。
- 继续使用 A04 的蓝色交互、系统字体、4px 间距网格、44 逻辑像素触控目标和浅深主题。本任务不新增 palette、字体或无来源装饰。
- 一级目的地按需初始化，切换后保留其列表、Tab 与滚动状态；不能因常驻导航同时发起所有页面请求。

## 进入、返回与深链

| 当前状态 | 用户动作 | 结果 |
|---|---|---|
| 任一一级目的地 | 点击另一个主导航项 | 原地切换一级目的地，保留已访问页面状态 |
| 联系人选择好友 | 点击联系人 | 打开对应私聊并切回“消息” |
| 新建群聊成功 / 群详情进入聊天 | 完成或点击进入 | 打开群会话并切回“消息” |
| 普通或广播通知 | 点击系统通知 | 校验节点、账号及同步就绪后进入消息或广播详情；目标失效回到安全列表 |
| 手机会话详情 | 系统返回 / 标题返回 | 回到会话列表 |
| 手机非消息一级页 | 系统返回 | 回到“消息”，再次返回才允许离开应用 |
| 模态页或二级详情 | 系统返回 | 只关闭当前详情，不跳过一级页 |

页面标题、按钮、提示和完成反馈必须使用同一动作名称。加载、空、错误、拒绝和不可用状态留在所属目的地内；不因入口统一而把 Deferred 功能显示成可完成操作。

## 徽标与状态

### 凭证选择、取消与重试

- 选择图片只是准备输入，不等于提交回执；只有服务端确认完成后才显示完成状态并移出待办。
- 取消系统选择器回到原详情，不显示成功，不复用其他操作留下的旧文件，也不改变服务端完成状态；用户可在同一详情重新发起。
- 选图、读取、上传与完成提交属于同一次办理。进行中阻止重复办理；取消或失败后恢复可操作状态，错误留在当前详情，不要求退出应用后重试。
- 文件内容、大小、资格与权限检查仍然有效；系统选择器的过滤能力不能代替应用和服务端校验。Web 与移动端可采用不同选择器，但遵循相同提交边界。

广播优先级和回执使用 Web `BroadcastWorkspace` 的现有产品词汇：普通通知、重要通知、紧急广播；等待确认、无需确认、已送达、已查看、已收到、已执行、需要支援、已过期。Flutter列表、详情和按钮使用相同文案，提交值仍为服务端协议枚举；未知自定义回执保留原名称，不能误译成已完成。协议映射位于 `apps/flutter-prototype/lib/ui/broadcast_labels.dart`。

- 消息徽标只表示未读消息；联系人徽标只表示待处理申请；广播徽标只表示待办广播。三者不能相加成一个含义不明的红点。
- 计数来源必须是当前账号和节点的权威状态；恢复同步前不得展示旧账号数字。
- Flutter B02 第一版先统一入口和返回路径。跨端徽标来源、通知深链完整状态与真实设备读屏仍按 A07C 验收，不因本规范存在而标记完成。

## 验收基线

1. 320px 与常用手机宽度下四个一级入口无需滚动或打开菜单即可触达。
2. 1.4 倍文字、浅色和深色下无溢出，主要入口有可朗读标签。
3. 联系人 / 群聊进入会话、非消息页系统返回、会话内系统返回符合上表。
4. Android 虚拟机只用于布局和点击流程；Android 实体设备、OEM 返回、读屏、性能和发布门禁仍分别记录。
5. Web / 桌面主导航、列表标题/搜索和空状态统一为“联系人 / 群聊”；“添加好友 / 好友申请”仍表示关系操作，不机械替换。Flutter消息主导航徽标使用同步就绪后的会话未读总数，99以上显示99+，读屏保留准确数量；断线或无账号时隐藏。Flutter联系人徽标读取当前账号待处理的收到申请（status=0），广播徽标读取服务端pending广播列表；两者独立去重、独立更新，失败/断线/账号切换时隐藏未知数量。首次同步就绪、对应实时事件、本地办理成功、切换一级目的地和重新连接时重新读取；完整业务页面仍按需初始化。这些徽标不使用消息总数代替，不新增轮询保活。广播截止时间触发一次服务端重读；服务器仍返回过期待办时最多追加五次共享重查，不按本机时间擅自扣减数量，断线/换账号/销毁取消定时器。无事件到期已有受控回归，设备端到端刷新仍需验收。
